# 흑우키우기 (Black Bull)

주차 턴제 주식 육성 게임. 중소기업 3년차 직장인 **김흑우**가 3년(156턴, 1턴 = 1주) 동안
주식으로 무엇을 잃고 얻는지에 대한 이야기.

톤은 자조적 현실(매운맛)이다. 물타기·존버·상투·손절·리딩방·곱버스·빚투를 전부 다루되
미화하지 않고 결과로 대가를 보여준다.

## 실행

```bash
pnpm install
pnpm dev            # 개발 서버 (http://localhost:5173)
pnpm build          # 프로덕션 번들
pnpm preview        # 번들 미리보기 (http://localhost:4173)
pnpm test           # 전체 테스트 (core + sim + app)
pnpm typecheck      # 전체 타입체크
pnpm sim -- --runs 2000 --strategy buyhold   # 밸런싱 시뮬
```

`--strategy`는 일곱 가지다. **이름은 실제 동작 그대로다** — 게이트 제목·CLI 출력·README 표에
그대로 드러나는 자리라, 이름이 거짓이면 게이트의 의미도 거짓이 된다.

| 전략 | 동작 | 평균 노출도 |
|---|---|---|
| `cash` | **스스로는** 매매하지 않는다. 월급만 받는 **'거의 무매매' 기준선** | 5% |
| `seedhold` | 턴 1에 **시드머니의 90%만** 넣고 156턴 방치. 월급은 계속 현금으로 쌓인다 | 40% |
| `buyhold` | **진짜 존버.** 매 턴 현금의 90%를 넣고 절대 팔지 않는다 | 99% |
| `momentum` | 최근 3턴 상승률 1등으로 갈아탄다 | 79% |
| `random` | 무작위 매매 | 52% |
| `panic` | 오르면 사고 내리면 판다 — 전형적인 흑우 | 96% |
| `labor` | **노동 특화 무매매.** 주식은 한 주도 안 사고 야근만 판다 | 4% |

`cash`·`labor`가 **완전한** 무매매가 아닌 이유: `buyStockPct` 이벤트가 플레이어의 주문
없이도 매수를 일으킨다. 전략 코드로는 막을 수 없어 잔여 노출이 남는다(Ruling 72 — 당시
근거였던 '물타기 카드'는 스펙 §2.4에서 종목 상세의 버튼으로 옮겨가 카드 풀에 없다.
남은 원인은 이벤트 하나뿐이고, 200판 실측으로 `cash` 6.8% / `labor` 3.7%다). 이 잔여 노출은 `cash`의 성과를 (기대값이 양수인 시장이므로) **끌어올리는**
쪽이라, `seedhold > cash × 1.03` 게이트를 통과하기 더 어렵게 만든다 — 게이트가 느슨해지는
방향이 아니므로 정당성은 훼손되지 않는다.

**전략을 비교할 때는 노출도를 맞춰야 한다.** `panic`은 매 턴 자본의 95%를 굴리므로
올바른 비교 대상은 `cash`가 아니라 `buyhold`다. `cash`와 비교하면 "뇌동매매가 무매매와
비슷하다"(−1%)로 보이지만, 노출을 맞추면 **중앙값 −27%**다.

## 한 주에 무슨 일이 일어나는가 — 행동력 · 등급 · 슬롯

1턴은 1주다. 한 주에 플레이어가 하는 일은 **이번 주에 뽑힌 카드 4장 중 몇 장을 내는 것**
하나뿐이고, 몇 장을 낼 수 있는지는 장수가 아니라 **행동력 예산**이 정한다.
(1차 슬라이스의 `cardsPerTurn` — 재직 1장 / 퇴사 2장 — 은 사라졌다. 그 이름이 코드나
문서에 남아 있으면 낡은 것이다.)

**행동력** (`BALANCE.action`, `actionPoints(state)`)

```
행동력 = base(2) + floor(체력 / staminaPerAp(3)) + (퇴사면 unemployedBonus(2)),  상한 max(6)
```

퇴사가 카드 장수가 아니라 예산 보너스인 편이 의미상 맞다 — 야근을 안 하니 한 주가 통째로 남는다.
체력 스탯이 곧 예산이므로 다섯 스탯 중 체력만은 **매주 몇 장을 낼 수 있는가**를 직접 바꾼다.

**슬롯** (`BALANCE.slots`, `drawSlots`)

```
행동 슬롯 3칸 : 성장 6종 + 야근 중 셋      (중복 없이 뽑는다)
회복 슬롯 1칸 : 휴식 / 운동 / 존버 / 최존버와 소주 중 하나
```

**회복 슬롯은 행동력을 쓰지 않고, 어떤 상태에서도 잠기지 않는다.** 이건 취향이 아니라
교착 방지 불변식이다 — 회복이 예산을 먹으면 행동력 0·멘탈 바닥에서 아무 것도 못 하는
상태가 실제로 생긴다. `cardApCost`가 회복 카드에 대해 항상 0을 돌려주고,
`cardLockReason`이 회복 카드는 다른 검사보다 **먼저** null로 빠져나간다.

**등급** (`BALANCE.grade`, `rollGrade`)

카드는 슬롯에 뽑힐 때마다 `E · D · C · B · A · S` 중 하나가 **함께 굴려진다.** 성장해서
굳는 레벨이 아니라 매주 다시 굴리는 운이다 — 같은 카드가 이번 주엔 A로, 다음 주엔 D로 뜬다.

```
효과   = 기본효과 × grade.mul[등급]          (E 0.4 … S 3.2)
현금   = 기본금액 × grade.cashMul[등급]      (E 0.25 … S 1.0)  ← 현금만 별도 곡선
행동력 = grade.ap[등급]                      (E·D 1, C·B 2, A·S 3)
컨디션 = 기본소모 × grade.mul[등급]
```

**현금 델타만 별도 곡선(`cashMul`)을 쓰는 이유**는 `balance.ts` 주석에 길게 적혀 있다.
요약하면 `mul`을 현금에도 곱하면 야근 S가 턴당 576,000원이 되어 **무위험 노동이 월급의
3.16배**가 된다 — 투자 게임에서 노동이 차익거래가 되면 장르가 붕괴한다. `cashMul`은
"야근 S등급이라도 턴당 월급(`employedNet / payPeriod`)을 넘지 않는다"를 만족하도록 골랐고,
`labor` 전략과 그 게이트가 이 성질을 지킨다.

등급 분포는 **대응 스탯**(분석 카드↔분석력 …)이 높을수록 상위로 밀린다(`grade.statShift`).
그래서 초반엔 E·D만 뜨고 후반엔 A·S가 섞인다 — `pnpm sim`의 `슬롯 등급` 줄이 그 이동(Δ)을 찍는다.

**리롤** (`BALANCE.reroll`, `rerollSlots`)

```
리롤 = base(1) + floor(인맥 / networkPer(3)),  상한 max(4)   — 매 턴 리셋
```

**행동 슬롯 3칸만** 다시 굴린다. 회복 슬롯은 리롤 대상이 아니다(위 불변식과 같은 이유).
`base`가 없으면 인맥 0인 초반에 뽑기 운을 완화할 수단이 아예 없어진다.

> 등급 굴림·슬롯 뽑기·리롤은 전부 `GameState.rng`를 지난다. 시드가 같으면 156턴이
> 그대로 재현된다는 성질은 이 셋을 넣은 뒤에도 유지된다.

**1턴차에 카드가 잠겨 보이는 것은 정상이다.** 20,000시드 실측으로 4칸 중 잠긴 칸이
**0칸 47.49% / 1칸 47.24% / 2칸 5.15% / 3칸 0.125%**다. 원인은 둘뿐이다 —
`리포트 정독`이 `tierMin: 2`라 개미 티어 전에는 잠기고(42.7%: 행동 카드 7장 중 1장을
3칸에 뽑으니 3/7과 같다), A·S로 뜬 카드가 ⚡3인데 1턴 예산이 2다(15.2%).

**행동 카드를 한 장도 못 내는 판은 20,000시드 중 25판(0.125%)** — 위 '3칸 잠김'과
같은 판이다(행동 슬롯 3칸이 전부 잠긴 경우). 그래도 **교착은 아니다**: 회복 슬롯은
정의상 잠기지 않고 행동력을 쓰지 않으므로 그 판도 카드를 내고 턴을 넘길 수 있다.
리롤(1턴에도 최소 1회)로 행동 슬롯을 다시 굴릴 수도 있다.

## 구조

- `packages/core` — 순수 함수형 게임 코어. 런타임 의존성 0개, React 의존성 없음.
  모든 규칙과 데이터가 여기 있다
- `packages/sim` — 코어를 headless로 수천 판 돌려 밸런스를 검증하는 CLI + 게이트 테스트
- `packages/app` — React + Vite 프론트엔드 (뷰 전용)

의존 방향은 `app → core`, `sim → core`뿐이고 역방향은 없다.

핵심 API는 `initGame(seed)` / `advanceTurn(state, cardIds)` / `buy` / `sell` 넷이다.
상태는 불변이고 난수는 시드 고정이라, 시드만 있으면 156턴 전체가 재현된다.
`core`·`sim`에서는 `Math.random` · `Date.now` · `new Date`를 쓰지 않는다.

## 밸런싱

**튜닝 가능한 수치는 전부 `packages/core/src/balance.ts`의 `BALANCE` 객체 하나에만 둔다.**
드리프트, 국면 전이 가중치, 엔딩 경계, 멘탈·컨디션 계수, 티어 문턱이 모두 여기 있다.
다른 파일에 숫자를 복사해 두면 시뮬로 튜닝해도 게임이 안 바뀐다.

### `pnpm sim`으로 밸런스를 확인하는 법

```bash
pnpm sim                                      # buyhold 1,000판 (기본값)
pnpm sim -- --runs 2000 --strategy panic      # 전략·판수 지정
pnpm --filter @bb/sim test                    # 게이트 15개를 테스트로 돌린다
```

`--` 뒤에 인자를 넣어야 pnpm이 아니라 CLI로 전달된다. 판수는 클수록 안정적이고,
2,000판이 몇 초 걸린다. **CLI는 판정하지 않고 숫자만 찍는다** — 판정은 게이트(테스트)의 몫이다.

읽는 순서:

| 출력 줄 | 무엇을 보는가 |
|---|---|
| `자산 중앙값` / `P10 / P90` | 분포. 중앙값만 보면 꼬리에서 벌어지는 일을 놓친다 |
| `종목별 최종가 배율` | **어떤 종목이 시드와 무관하게 확정 전멸하는가.** 자산 분위수로는 안 보인다 |
| `흔들림 겪은 판 %` / `멘탈 교착률` | 멘탈 시스템이 죽었는지 / 회복 슬롯이 일하고 있는지 |
| `턴당 행동력` / `턴당 리롤` | 예산이 남아도는가 — 남으면 선택이 만들어지지 않는다 |
| `슬롯 등급 초반 → 후반 (Δ)` | 스탯이 등급을 실제로 밀고 있는가 |
| `캐릭터 표정` / `칭호 부여율` | 축이 상수로 붕괴했는가 (100%나 0%에 붙어 있으면 축이 아니다) |
| `엔딩 분포` | 한 종류로 쏠리는가 |

### 게이트 15개 (`packages/sim/src/balance.test.ts`)

| 게이트 | 뜻 |
|---|---|
| 신용 미사용 전략에서 파산이 원리적으로 발생하지 않는다 | 사놓고 버티면 망하진 않는다. **파산율 0의 이유가 "안전해서"가 아니라 "아무도 대출을 안 불러서"임을 표면에 남긴다**(Ruling 16) |
| 대출 문턱 자체에는 도달한다 | 신용이 죽은 원인이 문턱 높이가 아님을 고정한다 |
| `panic` 중앙 자산 < `buyhold` 중앙 자산 × 0.85 | 뇌동매매는 확실히 손해다 (**노출을 맞춘 비교**) |
| `seedhold` 중앙 자산 > `cash` 중앙 자산 × 1.03 | **투자할 이유가 있다.** 마진 없는 `>`는 "차이 2,906원"도 통과시킨다 |
| 종목별 최종가 상승률이 15%~95% 안에 있다 | **어떤 종목도 시드와 무관하게 확정 승리·패배가 아니다** |
| 비ETF 종목 최종가 배율의 중앙값 > 1 | **시장 자체가 3년 뒤 우상향한다** (얇은 포지션을 통하지 않고 직접 측정) |
| `buyhold` 흔들림 발생 판이 10%~90% | **멘탈 시스템이 살아 있다** (늘 발동해도, 한 번도 안 발동해도 실패) |
| 1주 매수의 흔들림 < 10%, 몰빵은 > 15%이고 3배 이상 | **멘탈 피해가 노출도를 따라간다** (1주와 몰빵이 같으면 실패) |
| `labor`(야근 특화)가 `seedhold`를 이기지 못한다 | **노동이 무위험 차익거래가 아니다.** `grade.cashMul`을 옛 `grade.mul`로 되돌리면 여기서 깨진다 |
| 짙은 노출 투자(`buyhold`)가 `labor`를 확실히 이긴다 | 위 게이트의 반대 방향 — 노동을 너무 눌러도 안 된다 |
| 행동력이 대부분의 턴에서 실제로 소모된다 | 예산이 남아돌면 **선택이 만들어지지 않는다** |
| 등급 분포가 후반에 상위로 이동한다(Δ > 0.5) | 스탯이 등급을 민다(`grade.statShift`). 계수를 0으로 만들면 즉시 red |
| 회복 슬롯이 멘탈 교착을 막는다(교착률 < 20%) | 회복 슬롯 불변식이 **실제 플레이에서** 일하고 있는가 |
| 캐릭터 표정 3종이 실제 플레이에서 모두 나타난다 | 표정 축이 상수로 붕괴하지 않았는가 |
| `random` 엔딩 4종 이상, 최다 엔딩 < 70% | 결과가 한 종류로 쏠리지 않는다 |

게이트를 통과시키려고 **게이트를 낮추거나 시드 창을 갈아끼우지 않는다.** 게이트가 깨지면
고쳐야 할 것은 `BALANCE` 값이고, `BALANCE`를 건드릴 때는 **게이트 15개를 함께 돌린다** —
행동력·등급·리롤은 서로 물려 있어서 한 값만 움직여도 다른 게이트가 넘어간다.

### 시장 모형 한 줄 요약

주가는 `국면 드리프트 × 베타 + 정규 노이즈 × 국면 변동성 + 이벤트 충격 × (1+hype) ×
BALANCE.impact.mul + 평균회귀(적정가 대비)`로 움직인다.

- **적정가(fundamental)는 매 턴 `BALANCE.fundamentalGrowth`만큼 자란다.** 국면 드리프트는
  평균회귀가 되돌리지만 이 성장분은 되돌리지 못하므로, 장기 보유가 보상받는 원천이 여기다.
  이 값이 0이면 주가는 고정된 적정가 주위를 맴돌 뿐이다.
- **이벤트 충격이 가장 큰 채널이다.** 국면 드리프트(턴당 ±0.001~0.01)보다 한 자릿수 크다.
  세기는 `BALANCE.impact.mul`로 조절하지만, **방향 편향은 이벤트 데이터 자체로 관리한다** —
  각 채널(`market` / `sector:*` / `stock:*` / `fundamentalMul`)이 양방향 이벤트를 짝으로
  갖고 가중 기대값이 0 근처여야 한다. `packages/core/src/events/content.test.ts`의
  "임팩트 채널 균형" 블록이 이걸 강제한다.
- 지수 ETF는 개별 종목·섹터 뉴스를 받지 않고 **시장 충격만** `BALANCE.etfShockMul` 배수로
  받는다(레버리지 2배, 곱버스 −2배). `beta`만 뒤집어 두면 국면 드리프트만 반대가 되고
  뉴스에는 시장과 같은 방향·1배로 움직여서 이름값을 못 한다.
- **멘탈 피해는 노출도**(보유평가액 / 총자산)**에 비례한다** — `BALANCE.mental.lossExposureFull`
  에서 100%로 포화한다. `portfolioLossPct`가 보유 원가 대비라 이 가중이 없으면 7만원짜리
  1주와 몰빵이 같은 피해를 입는다(실측: 가중 없이 1주 56% vs 몰빵 50% — 역전이었다).

> **채널 균형은 weight 비중이 아니라 채널 가중평균으로 관리한다.** 이벤트를 60 → 76종으로
> 늘리면서 news·company의 weight 비중이 38% → 47.5%가 됐지만, 실제 발화 기준으로는 모든
> 카테고리에서 **텍스트 1종당 반복이 줄었다**(personal 7.3 → 5.6회/판). 즉 희석이 아니라
> 콘텐츠 증가다. **"news 비중이 높다"를 근거로 news 이벤트를 줄이면 채널 균형이 깨진다** —
> 짝지어진 상승·하락 이벤트를 한쪽만 지우게 되기 때문이다. 비중이 신경 쓰이면
> news를 줄이지 말고 다른 카테고리를 늘려라.

### 화면에 보이는 수익률의 기준선

HUD의 수익률은 **시드머니 대비가 아니라 무매매 기준선 대비**다
(`noTradeBaseline = seedMoney + trackers.netPayroll`). 시드머니를 기준선으로 삼으면 3년간
자동 입금되는 가처분소득 약 2,850만원이 통째로 '투자 수익'으로 계상돼, 주식을 한 주도
사지 않은 판이 최종턴에 **+1,000%**를 띄운다(최종 리뷰 C1 실측 +1049.2%). 엔딩 경계
(`BALANCE.endings`)가 이미 같은 기준선에 정박해 있으므로, 화면과 엔딩이 이제 같은 잣대를
쓴다 — 같은 판에서 HUD가 +1049%인데 엔딩은 "누구한테 자랑하긴 애매한 숫자"인 모순이 사라진다.

홈 화면 캐릭터의 표정(`normal`/`joy`/`shaken`)도 같은 수익률을 쓴다(`moodOf`). 흔들림이면
shaken, 멘탈이 `BALANCE.mood.joyMental` 이상이면서 수익률이 `joyRoiPct` 이상이면 joy,
나머지는 normal이다. 세 표정이 실제로 다 나오는지는 `pnpm sim`의 **캐릭터 표정** 줄에서
보이고, `packages/sim/src/balance.test.ts`의 게이트가 붕괴를 막는다.

> **밸런싱할 때 반드시 보는 두 줄.** `pnpm sim`의 **종목별 최종가 배율**과 **흔들림 겪은 판 %**.
> 자산 분위수만 보면 "10종 중 5종이 시드와 무관하게 확정 전멸"과 "멘탈 시스템이 한 번도
> 발동하지 않음"을 둘 다 놓친다 — 실제로 놓쳤다.

## 저장 스키마 — `SAVE_VERSION` 규율

`packages/app/src/store/store.ts`의 `SAVE_VERSION`은 **저장된 `GameState`의 스키마
버전**이다. `readSave()`는 버전이 다르면 그 저장을 버리고 `null`을 돌려준다.

> **`GameState`(또는 그 하위 타입)의 구조를 바꾸면 같은 커밋에서 `SAVE_VERSION`을 올린다.**

**현재 값은 `4`다.** 지금까지 올린 이유:

| 버전 | 올린 이유 |
|---|---|
| v1 | 최초 |
| v2 | `trackers.netPayroll` 추가 — HUD가 렌더 즉시 읽는다(없으면 수익률이 `NaN%`) |
| v3 | `slots` · `rerollsLeft` 추가 — 턴 루프가 이 둘을 소비한다. v2 저장은 카드가 한 장도 안 떠 **턴을 넘길 수 없다** |
| v4 | `trackers`에 `feesPaid` · `taxPaid` · `peakAssets` · `maxDrawdownPct` · `tradeCount` 5개 추가 — 엔딩(잔고증명서)이 읽는다. 없으면 `Math.max(undefined, x)`가 `NaN`이 되어 최대 낙폭이 영구히 오염된다 |

올리지 않으면 구버전 저장이 신버전 코드로 그대로 로드되고, 새 코드가 기대하는 필드가
없는 채로 렌더에 들어가 **흰 화면**이 된다. 이건 타입 검사가 못 잡는다 — 저장은
`localStorage`의 JSON이라 컴파일 타임에 존재하지 않기 때문이다. 규율로만 막을 수 있다.

구조를 바꾸는 변경의 예:
- 필드 추가·삭제·이름 변경 (`player`, `stocks`, `trackers`, `flags` …)
- 필드 의미 변경 (단위·기준 변경 포함. 예: 비율 0~1 → 0~100)
- 배열 원소 형태 변경 (`holdings[]`, `pendingChoices[]` …)

바꾸지 않아도 되는 예: `BALANCE` 숫자 튜닝, 문구·아트 교체, 렌더 전용 변경.

`SAVE_KEY`는 `SAVE_VERSION`에서 파생시킨다(`blackbull.save.v${SAVE_VERSION}`) — 리터럴로
`v1`을 박아두면 버전을 올렸을 때 키 이름만 거짓말이 된다.

저장 검증(`readSave`)을 통과해도 렌더가 죽을 수 있고(예: `holdings`가 사라진 종목을 가리킴),
저장과 무관한 코드 버그로도 죽는다. 그래서 최상위에 `ErrorBoundary`
(`packages/app/src/ErrorBoundary.tsx`)를 두고 버튼 두 개를 준다: **다시 시도**(저장을 건드리지
않는다 — 일시적 예외면 진행이 살아난다)와 **새 판으로 시작**(세이브를 지운다).
도감(`blackbull.codex.v1`)은 회차 기록이라 어느 쪽에서도 지우지 않는다.

## 레이아웃 감사 (`scripts/layout-audit.mjs`)

홈 화면의 세로 예산은 **단위 테스트로 증명되지 않는다** — jsdom은 레이아웃을 계산하지
않는다. `packages/app/src/design/layout.test.tsx`가 하는 일은 *알려진 우회 수단*
(`flex`·`min-height`·`overflow`·`position`·`display`·`margin`)을 하나씩 막는 **조기
경보**이고, 그 목록은 **완전하지 않다** — `transform`·`clip-path`·`:has()`처럼 아직
열거하지 않은 메커니즘은 얼마든지 남아 있다.

> **결과의 권위는 이 스크립트에 있다. 레이아웃을 건드리는 변경은 반드시 돌려라.**
> 단위 테스트가 green인 것은 "알려진 우회가 없다"는 뜻이지 "화면이 멀쩡하다"는 뜻이 아니다.

```bash
pnpm --filter @bb/app build && pnpm --filter @bb/app preview   # 다른 터미널
node packages/app/scripts/layout-audit.mjs --url http://localhost:4173/               # 390×844, 156턴
node packages/app/scripts/layout-audit.mjs --url http://localhost:4173/ --height 667   # 짧은 기기
node packages/app/scripts/layout-audit.mjs --url http://localhost:4173/ --seed 42      # 시드 고정
node packages/app/scripts/layout-audit.mjs --url http://localhost:4173/ --turns 20     # 부분 표본(빠른 확인)
```

| 옵션 | 뜻 |
|---|---|
| `--url` | 미리보기 주소 (기본 `http://localhost:4173/`) |
| `--width` · `--height` | 뷰포트 (기본 390×844) |
| `--seed` | 게임 시드 (기본 고정값). 앱이 `?seed=`를 읽어 그 판을 재현한다 |
| `--turns` | 몇 턴까지 볼지 (기본 156 = 완주). **156 미만은 '표본'이고 결과가 아니다** |
| `--pixels off` | 픽셀 오라클 끄기 |
| `--pixel-debug 1` | 표본마다 픽셀 수치를 찍는다(임계값을 다시 잴 때) |

**종료 코드:** `0` 완주 통과 · `1` 위반 · `2` 부분 표본(위반 없음, 판정 아님).
`--turns`로 줄인 런의 "통과"를 근거로 인용하면 안 된다 — 붐비는 턴에서만 드러나는 결함이
있다(실측: `display: contents` 결함은 12턴에서 통과하고 156턴에서만 잡혔다).

한 판(기본 156턴)을 자동으로 끝까지 돌면서 매 턴 **두 번**(카드 고르기 전/후)
`한 주 넘기기` 버튼을 잰다. 재는 것은 **메커니즘이 아니라 결과**다:

| 지표 | 무엇이 틀렸을 때 나빠지는가 |
|---|---|
| 존재 · 크기(w·h > 0) | 버튼을 안 그리거나 `display:none`으로 접었을 때 |
| 터치 타깃(height ≥ 44) | 전역 제약 위반 |
| 뷰포트 포함(상·하·좌·우) | 무엇이든 버튼을 화면 밖으로 밀었을 때 |
| **히트테스트**(`elementFromPoint`가 버튼인가) | 버튼을 덮는 요소가 클릭을 가로챌 때 |
| **가시성**(`Element.checkVisibility`) | `display`·`visibility`·`opacity:0`·`content-visibility` |
| **픽셀**(버튼 rect로 크롭한 페이지 스크린샷) | **그 자리에 아무것도 안 보일 때** — 무엇이 원인이든 |

하나라도 위반이면 **종료 코드 1**. 표본이 0건이어도 실패한다.

픽셀 오라클이 마지막 겹이다. 기하와 히트테스트가 전부 정상인데 버튼이 안 보이는 경우가
실제로 있었다 — `filter: opacity(0)`(`checkVisibility`는 filter를 안 본다), `opacity: .01`
(정확히 0만 false), 다른 요소가 만든 `pointer-events: none` 커튼(`elementFromPoint`가
정의상 못 본다). 셋 다 **메커니즘이 다르고 결과는 같다.** 그래서 메커니즘을 열거하는 대신
결과를 묻는다: *그 자리에 무언가 보이는가?* 임계값은 156턴 312표본 실측에서 골랐다
(정상 잉크 3.52~3.75% / 공격 0.00~1.81% → 경계 2.0%). 매 실행 **관측된 최소 잉크**를
출력하므로, 그 값이 경계에 가까워지면 임계값을 다시 재야 한다는 신호가 된다.

> **왜 이 지표인가.** 예전에는 `document.documentElement.scrollHeight`로 쟀는데,
> `.app { height: 100dvh; overflow: hidden }` 아래에서 그 값은 뷰포트를 넘을 수가 없어
> **어떤 레이아웃에서도 통과하는 무효한 지표**였다. 그 다음 버전의 `clearance`(여유)도
> 절반만 옳았다 — 버튼이 없으면 여유가 최선값으로, 덮여 있어도 정상값으로 나왔다.
> **부재를 만족으로 읽는 검사**는 이 저장소가 네 번 밟은 함정이다. 지표를 고를 때는
> 언제나 먼저 물어라: *이 값이 나빠질 수 있는가? 무엇이 틀렸을 때 나빠지는가?*

> **알려진 한계 (2026-08-27 기준, 실측으로 확인한 것만 적는다).**
> - 감사가 보는 것은 **'한 주 넘기기' 버튼 한 곳**이다. 카드·탭바·오버레이가 안 보이게
>   되는 것은 어떤 지표도 보지 않는다.
> - 픽셀 오라클은 **버튼 자리에 무언가 보이는가**만 묻는다. 글자가 **읽을 수 있는지**
>   (대비·잘림·엉뚱한 글자)는 묻지 않는다. 예: 라벨을 다른 문구로 바꿔치기하면 통과한다.
> - 임계값(잉크 2.0%)은 **웹폰트가 로드되지 않은 환경**에서 잰 값이다. 폰트가 바뀌면
>   정상값이 움직일 수 있다 — 그때는 `--pixel-debug 1`로 다시 재라.
> - 정적 CSS 훑기(`design/layout.test.tsx`)의 범위는 `src/**/*.css` + `index.html`의
>   인라인 `<style>`이다. `<link>`로 불러오는 **외부 스타일시트는 범위 밖**이다.
> - 감사는 CI에 없다. 사람이 돌려야 한다.

**Playwright는 선택적 외부 의존이다** — 무거운 브라우저 의존성을 `package.json`에
올리지 않았고 CI 게이트도 아니다(별개 결정). 없으면 스크립트가 안내와 함께 비영점 종료한다.

```bash
npm i -g playwright && npx playwright install chromium
# 경로가 특이하면:
PLAYWRIGHT_MODULE=<playwright의 index.mjs> PLAYWRIGHT_CHROMIUM=<크롬 실행파일> \
  node packages/app/scripts/layout-audit.mjs --url http://localhost:4173/
```

## 상장법인목록 갱신

`packages/core/data/listed-companies.json`은 KRX 상장법인 **회사명만** 뽑아 담은 배열이다
(현재 2,761개). 종목명이 실존 상장사와 부딪히지 않는지를 `packages/core/src/market/stocks.test.ts`가
이 파일로 검사한다 — 스크립트가 아니라 테스트라서 종목을 추가할 때마다 자동으로 걸린다.

갱신 방법:

1. [kind.krx.co.kr](https://kind.krx.co.kr) → **상장법인상세정보 → 상장법인목록** → **엑셀** 다운로드
2. 받은 파일이 `상장법인목록.xls`인데, **확장자만 `.xls`이고 실제 내용은 EUC-KR로 인코딩된
   HTML `<table>`이다.** 여기서 반드시 한 번 넘어진다:
   - 엑셀·LibreOffice는 열어 주지만(HTML로 인식) `xlrd`·`openpyxl` 같은 파서는 전부 실패한다
   - UTF-8로 읽으면 한글이 통째로 깨진다 — **`euc-kr`(또는 `cp949`)로 디코딩**해야 한다
3. `<td>` 첫 열(회사명)만 뽑아 문자열 배열로 저장한다. 종목코드·업종 등 나머지 열은 쓰지 않는다.

```bash
# 예시 — 파서는 무엇을 쓰든 상관없다. 지켜야 할 것은 둘뿐이다:
#   (1) 엑셀 파서가 아니라 **HTML 파서**로 읽는다 (read_excel ❌ / read_html ✅)
#   (2) **euc-kr**로 디코딩한다
python3 -c "
import pandas as pd, json          # pandas + lxml(또는 bs4·html5lib)이 필요하다
df = pd.read_html('상장법인목록.xls', encoding='euc-kr')[0]
names = sorted({str(x).strip() for x in df['회사명']})
json.dump(names, open('packages/core/data/listed-companies.json', 'w'), ensure_ascii=False)
print(len(names))
"
```

갱신 후 `pnpm --filter @bb/core test`를 돌린다. 새로 상장된 회사가 우리 종목명과 겹치면
'종목명 법적 안전성' 블록이 red가 된다 — **그때 고칠 것은 테스트가 아니라 종목명이다.**
새 이름은 기존 규칙을 따른다: **순우리말 어근.** 실존 상장사는 대부분 한자어·영어
어근이라 순우리말은 구조적으로 충돌 확률이 낮다(스펙 §7).
