# 흑우키우기 (Black Bull) — 설계 문서

- 날짜: 2026-08-25
- 상태: 사용자 승인 완료 (브레인스토밍 4개 섹션 개별 승인)
- 범위: 1차 버티컬 슬라이스 (완주 가능한 최소 완성본)

## 1. 개요

"수험생 키우기"류의 주차 턴제 육성 게임. 플레이어는 중소기업 3년차 직장인
**김흑우**가 되어 3년(156턴, 1턴 = 1주) 동안 주식 투자를 한다. 실제 주린이의
경험(물림, 뇌동매매, 뒷북, 리딩방)을 시스템으로 재현하고, 밈을 시스템
용어로 사용하며, 멀티엔딩으로 회차 반복을 유도한다.

톤은 **자조적 현실(매운맛)**: 물타기·존버·떡상·상투·손절·리딩방·곱버스·빚투를
전부 다루되, 실제 도박·불법 금융을 미화하지 않고 결과로 대가를 보여준다.

### 핵심 결정 요약

| 항목 | 결정 |
|---|---|
| 핵심 루프 | 주차 턴제 육성 (1턴 = 1주, 총 156턴) |

| 아키텍처 | 순수 함수형 결정론 코어 + React는 뷰 전용 |

| 아트 | SVG 카툰, 레지스트리로 추상화 → 추후 AI 일러스트 교체 가능 |
| 성장 | 자산 티어 6단계 × 육성 스탯 5종 |
| 회차 | 3년 156턴 + 멀티엔딩(8종) × 칭호(7종) |

| 저장 | 클라이언트 전용 (localStorage), 백엔드 없음 |
| 1차 목표 | 플레이 가능한 버티컬 슬라이스 |

## 2. 세계관·주인공·성장 축

### 2.1 주인공

**김흑우**(이름 변경 가능), 27세, 중소기업 3년차.

- 월 실수령 245만원
- 고정지출 월 172만원 (월세 55 / 대출이자 31 / 통신·교통·식비 86)
- 가처분 월 73만원 → 매달 예수금에 자동 입금
- 시드머니 300만원 (적금 해지)

이 수치가 게임 전체의 척도다. 손실액이 "몇 달치 저축"인지 환산되는 순간
공감대가 생긴다.

### 2.2 프롤로그

회식에서 동기 박대박이 계좌 인증(+3,240만원, +412%)을 돌린다. 주인공은
새벽 2시에 증권사 앱을 깔고 적금을 깬다. "나만 없어 주식."
2회차부터 프롤로그 스킵 가능.

### 2.3 시장 국면 (regime)

시장 전체가 국면을 갖고 흐른다: `활황 → 과열 → 폭락 → 침체 → 회복`.
각 국면은 8~30턴 지속. 회차 시작 시 156턴 전체 국면 시퀀스를 **미리 생성**한다
(마르코프 체인 + 제약: 폭락 최소 1회 포함, 첫 국면은 폭락 아님).

국면 이름은 플레이어에게 표시하지 않는다. 뉴스 헤드라인 톤으로만 암시한다
(과열: "택시기사도 주식 얘기" / 침체: "증권사 지점 통폐합").
정보력이 높으면 국면 전환을 1~2턴 먼저 감지한다.

### 2.4 자산 티어 6단계

| 티어 | 총자산 | 해금 |
|---|---|---|
| 주린이 | ~1천만 | 대형주만. 호가창 미표시 |
| 개미 | 1천만~ | 코스닥·테마주, 뉴스 탭 |
| 불개미 | 5천만~ | 해외주식, 기업 리포트 |
| 슬기로운개미 | 1억~ | 신용·미수, 공매도 잔고 표시 |
| 슈퍼개미 | 5억~ | 레버리지/인버스 ETF |
| 큰손 | 30억~ | 지분공시. 본인 매수가 주가에 영향 |

티어는 자산 하락 시 **강등**되며, 강등 전용 컷신이 있다.

### 2.5 게이지와 육성 스탯

플레이어 상태는 **게이지 2종**(매 턴 변동하는 자원)과
**육성 스탯 5종**(행동으로 올리는 영구 능력치, 0~10)으로 구성된다.

**게이지 (0~100, 최대치는 전원 100 고정)**

- **멘탈** — 투자 판단력. 규칙은 §3 참조
- **컨디션** — 신체 상태. 낮으면 `야근으로 장 못 봄` 강제 스킵 턴 발생,
  0 도달 시 번아웃(3턴 행동 불가)

**육성 스탯 (0~10)**

- **강인함** — 멘탈 감소 저항: `실제 감소량 = 기본 감소량 × (1 − 강인함 × 0.06)`
- **체력** — 컨디션 감소 저항 (강인함과 동일 공식, 야근·과로 감소에 적용)
- **정보력** — 이벤트의 주가 반영 지연(0~3턴) 구간에 `루머` 카드로 미리 보임.
  0이면 주가가 이미 움직인 뒤에 뉴스를 본다
- **분석력** — 종목 상세의 `적정가 밴드`·`리스크 등급` 정확도. 낮으면
  **틀린 값을 확신에 찬 UI로 표시**한다 (주린이의 자기확신 재현)
- **인맥** — 지인·리딩방 정보 이벤트 빈도. 정보 품질은 인맥과 무관하게 랜덤.
  제안 거절 시 그 종목이 급등하는 연출만 있고 수치 페널티는 없다

### 2.6 조연 4인

| 인물 | 역할 | 아크 |
|---|---|---|
| 박대박 | 거울 | 회사 동기. 항상 앞서가다 후반 빚투로 무너진다 |
| 최존버 | 멘토 | 사내 은둔 고수. 15년 한 종목. 결정적 순간에 한마디 |
| 김실장 | 함정 | 리딩방 운영자. 첫 두 번은 실제로 맞춘다 |
| 엄마 | 현실 앵커 | 주기적 전화. "적금이나 들지." 엔딩에서 가장 무겁다 |

넷 다 엔딩·칭호 판정에 관여한다 (박대박 자산 초과 여부, 김실장 루트 진입
여부, 엄마 전화 무시 횟수 등).

### 2.7 밈 적용 원칙

밈은 장식이 아니라 **시스템 명칭**으로 쓴다: 상태이상 = `물렸다`,
버프 = `떡상각`, 회복 행동 = `존버`. 종목명·헤드라인은 실존 종목과
혼동되지 않게 비튼다 (`삼정전자`, `에코프로형제`, `두산로보뭐시기`).

## 3. 멘탈 시스템

### 3.1 증감 규칙 (턴당)

| 조건 | 변화 |
|---|---|
| 손실 구간에 있음 | −3 (고정) |
| 손실률이 이번 턴에 더 악화 | −(악화폭%p × 0.5) |
| 신용·미수 사용 중 | −8 |
| 현금 비중 50% 이상 | +5 |
| 회복 행동 카드 사용 | +20 |

이벤트 개별 증감은 이벤트 데이터에 정의하고 규칙에는 두지 않는다.
감소량에는 강인함 저항이 적용된다.

설계 근거: 손실 "보유"보다 손실 "악화"가 아프게 — 사람은 손실에 적응한다.
레버리지는 매 턴 멘탈을 태우고, 현금은 멘탈을 회복시킨다.

### 3.2 구간 2단계

**정상 (30~100)** — 페널티 없음.

**흔들림 (0~29)** — 강제 효과 2개:

1. **이성 카드 잠김** — `기업분석`·`리포트정독`·`공부` 계열 비활성화.
   남는 것은 `물타기`·`존버`·`커뮤니티 눈팅` 등
2. **손절 봉인** — 손실 −20% 이상 종목의 매도 버튼 잠김 ("손이 안 나간다")

### 3.3 불변 규칙 (데드락 방지)

**회복 카드(`휴식`·`운동`·`최존버와 소주`)는 어떤 상태에서도 절대 잠기지
않는다.** 흔들림 상태에서는 오히려 UI 최상단에 노출된다.

탈출 가능성 검증: 최악 케이스(폭락 + 신용 = −31/턴)에서도 추가 하락이
멈추면 −11, 회복 카드 +20으로 순 +9. 갇히는 구조가 없어야 하며, 이는
속성 테스트로 보증한다 (§8).

## 4. 시뮬레이션 코어

### 4.1 종목 모델

```ts
type Stock = {
  id: string
  name: string          // "삼정전자"
  sector: Sector        // 반도체·2차전지·바이오·조선·게임·금융·엔터·방산
  tierGate: Tier        // 매수 가능 최소 티어
  price: number
  fundamental: number   // 내재가치. 실적 이벤트로만 계단식 변동
  volatility: number
  beta: number          // 시장 민감도
  hype: number          // 테마성 0~1. 이벤트 충격 배율
}
```

### 4.2 주간 가격 갱신

```
r = 시장드리프트(국면) × beta
  + 개별노이즈 ~ N(0, volatility × 국면변동성배수)
  + 이벤트충격 × (1 + hype)
  + 평균회귀계수 × ln(fundamental / price)

price ×= exp(r)
```

평균회귀 항이 핵심: hype로 급등한 테마주도 fundamental이 따라오지 않으면
결국 회귀한다. `상투`가 시스템으로 성립하고, 분석력 스탯(적정가 밴드 =
fundamental 추정)이 의미를 갖는다.

### 4.3 국면 파라미터

| 국면 | 주간 드리프트 | 변동성 배수 |
|---|---|---|
| 활황 | +0.4% | ×1.0 |
| 과열 | +1.2% | ×1.4 |
| 폭락 | −3.5% | ×2.5 |
| 침체 | −0.3% | ×0.8 |
| 회복 | +0.8% | ×1.2 |

### 4.4 난수

`mulberry32` 시드 RNG를 `GameState` 내부에 `{ seed, counter }`로 보관.
시드만으로 156턴 전체가 재현된다 (버그 재현, 결정적 테스트, 리플레이).

### 4.5 턴 루프 API

```ts
buy(state, stockId, qty)   → GameState   // 턴 내 무제한
sell(state, stockId, qty)  → GameState
advanceTurn(state, cardId) → GameState   // 턴 종료 시 1회
```

`advanceTurn` 내부 순서:

1. 행동 카드 해결 (스탯·게이지·현금)
2. 국면 진행 + 전 종목 가격 갱신
3. 예약 이벤트 만기 처리 (delay 만료된 뉴스의 주가 반영)
4. 신규 이벤트 추첨 (조건 필터 → 가중 랜덤)
5. 멘탈·컨디션 정산
6. 4턴마다 월급 입금 / 생활비 출금
7. 티어 재평가 (승급·강등 컷신 플래그)
8. 종료 판정 (156턴 도달 또는 파산)

### 4.6 거래 비용

수수료 0.015%(매수·매도), 증권거래세 0.18%(매도). **필수 요소** — 이것이
없으면 단타가 수학적으로 우월해져 게임이 무너진다. 매주 전량 회전 시
156턴 동안 원금의 30% 이상이 비용으로 소멸하는 구조가 유지되어야 한다.

### 4.7 이벤트 시스템

전부 JSON 데이터. 코드는 인터프리터만 구현한다.

```ts
type GameEvent = {
  id: string
  category: 'news' | 'company' | 'personal' | 'social' | 'story'
  conditions: Condition[]   // 티어·턴범위·국면·스탯·보유종목·플래그
  weight: number
  oneShot: boolean
  impact?: { target: StockId | Sector; magnitude: number; delay: 0|1|2|3 }
  text: { title: string; body: string; speaker?: CharacterId }
  choices?: Choice[]        // 없으면 알림형
}
```

`delay`가 정보력 스탯의 존재 이유: 발생~반영 사이 구간에 정보력이 높으면
`루머` 카드로 미리 노출된다.

### 4.8 행동 카드

```ts
type ActionCard = {
  id: string; name: string; description: string
  cost?: { money?: number; condition?: number }
  effects: Effect[]
  requires?: Condition[]
  lockedWhenShaken: boolean   // 흔들림 구간에서 잠김
  isRecovery: boolean         // true면 절대 잠기지 않음
}
```

1차 구현 12장: `야근`(돈+, 컨디션−) `기업분석`(분석력+) `리포트정독`(분석력+)
`뉴스탐독`(정보력+) `커뮤니티눈팅`(정보력+, 멘탈−) `종토방투어`(인맥+)
`운동`(컨디션+, 회복) `휴식`(멘탈+, 회복) `최존버와소주`(멘탈++, 인맥+, 회복)
`물타기`(보유 손실 종목 추가매수) `존버`(무행동, 멘탈 소폭+) `주식스터디`(강인함+)

## 5. 엔딩·진행·분기

### 5.1 엔딩 8종 × 칭호 7종

엔딩은 자산 축, 칭호는 플레이 방식 축. 곱으로 수집 폭을 만든다.

**엔딩 (1차 구현 8종)**

기준선은 **시드머니가 아니라 "아무것도 하지 않았을 때의 최종 자산"**이다.
§2.1의 현금흐름이 3년간 가처분 73만 × 39개월 = **2,847만원**을 계좌에 밀어 넣으므로,
시드 300만원에 경계를 걸면 3년치 월급까지 통째로 날려야 `적금이나 들걸`에 닿는다
(그건 파산 영역이다). 실측 무매매 최종 자산 중앙값은 **약 2,900만원**이고,
아래 경계는 그 기준선과 티어 문턱(§2.4)에 맞춘 값이다.

| 엔딩 | 조건 | `BALANCE.endings` |
|---|---|---|
| 흑우의 전설 | 파산 (자산 ≤ 0 또는 반대매매 마이너스) | — |
| 적금이나 들걸 | 2,500만 미만 (무매매 기준선보다 확실히 못함) | `savingsBelow` |
| 본전이 어디야 | 2,500만 ~ 3,400만 (무매매 기준선 언저리) | `breakevenHigh` |
| 은행 이자보단 낫지 | 3,400만 ~ 1억 | — |
| 슬기로운 투자생활 | 1억 ~ 5억 (티어 '슬기로운개미' 문턱) | `wiseMin` |
| 슈퍼개미 | 5억 이상, 재직 중 (티어 '슈퍼개미' 문턱) | `superMin` |
| 파이어족 | 10억 이상 + 퇴사 | `fireMin` |
| 김실장의 후예 | 인맥 8+ & 김실장 루트 완주 (자산 무관) | — |

> **정정 이력(Task 24).** 이전 표의 "시드 < / 시드 ±10% / 시드 ~ 2배"는 §2.1의 월급 누적을
> 빠뜨린 산술이었다. 그 숫자로는 `적금이나 들걸`·`본전이 어디야`가 사실상 도달 불가였고,
> `은행 이자보단 낫지` 하나가 300만~1억 구간을 독식해 실측 엔딩이 2종으로 붕괴했다.
> 무매매 기준선으로 다시 정박했다. 그 결과 `은행 이자보단 낫지` 구간은 "시드~2배"가 아니라
> 기준선의 약 1.1배~3.4배가 됐다 — 상단을 티어 문턱(1억)에 맞추기로 한 결과다.
> **경계를 다시 만질 때는 `BALANCE.endings`만 고치고, 시드머니가 아니라 무매매 기준선
> (`pnpm sim -- --strategy cash`의 자산 중앙값)과 비교할 것.**

**칭호 (중복 가능, 엔딩명 앞에 붙음)**

`박대박을 이긴` · `엄마 몰래`(전화 3회+ 무시) · `강철멘탈의`(흔들림 0턴) ·
`한 번도 손절 안 한` · `빚 없이` · `존버한`(한 종목 52턴+ 보유) ·
`풀매수`(평균 현금비중 5% 미만)

## 7. 아키텍처

### 7.1 원칙

게임 로직 전체를 React를 모르는 순수 TypeScript 패키지로 분리한다.
`GameState`는 불변, 모든 전이는 순수 함수, 난수는 상태 내 시드 RNG.
콘텐츠(종목·이벤트·카드·엔딩)는 전부 JSON 데이터.

### 7.2 프로젝트 구조 (pnpm workspace)

```
black-bull/
├─ packages/
│  ├─ core/              # 순수 TS. React 의존성 0
│  │  ├─ src/
│  │  │   rng/           # mulberry32
│  │  │   market/        # 국면 생성, 주가 시뮬
│  │  │   turn/          # advanceTurn, buy, sell
│  │  │   events/        # 조건 평가·추첨·효과 적용
│  │  │   mental/        # 멘탈 규칙
│  │  │   endings/       # 엔딩·칭호 판정
│  │  └─ data/           # stocks.json events/*.json cards.json endings.json
│  ├─ sim/               # 밸런싱 CLI
│  └─ app/               # React + Vite
│      store/            # zustand — core 호출 + localStorage 영속
│      screens/          # Home Market Account Codex
│      art/              # 아트 레지스트리 + SVG 파츠
```

의존 방향: `app → core`, `sim → core`. `core`는 누구도 모른다.

### 7.3 아트 슬롯 (교체 가능성 요구사항)

모든 그림은 단일 컴포넌트 `<Art id="..." />`를 통해서만 렌더링한다.

```ts
// art/registry.ts — 교체는 이 파일에서만 일어난다
export const ART: Record<ArtKey, ArtSource> = {
  'char.tier1.shaken': { kind: 'svg', component: CharTier1Shaken },
  // AI 일러스트 교체 시: { kind: 'image', src: '/art/char_t1_shaken.webp' }
}
```

`ArtKey`는 유니온 타입 — 키 누락은 컴파일 에러. 게임 코드는 교체 시 한 줄도
변경되지 않는다.

1차 아트 키 약 60개: 캐릭터 6티어 × 3표정(정상·흔들림·환희), 조연 4,
컷신 10, 엔딩 8, 섹터 아이콘 8, UI 소품. 캐릭터는 공통 몸통 + 파츠
조합(표정·옷·소품)으로 제작해 실작업량을 줄인다.

### 7.4 저장

localStorage. 저장 대상: 현재 회차 `GameState` 직렬화 + 도감/기록.
스키마 버전 필드를 두어 추후 마이그레이션에 대비한다.

## 8. 테스트·밸런싱 전략

### 8.1 core 단위 테스트 (TDD)

- 주가 공식 각 항, 국면 생성 제약 (폭락 ≥ 1회, 첫 국면 ≠ 폭락)
- **멘탈 데드락 부재** — 손실 악화가 멈춘 임의의 상태에서 회복 카드
  반복 시 유한 턴 내 반드시 30 이상 복귀 (속성 테스트: 신용 미사용 시
  최악 순증가가 +17/턴 이상임을 보증)
- 이벤트 조건 평가·delay 처리·효과 적용
- 엔딩·칭호 판정 경계값
- 매매 회계 정확성 (수수료·세금 포함)
- 고정 시드 156턴 풀 플레이 스냅샷 (회귀 방지)

### 8.2 밸런싱 하네스

```
pnpm sim --runs 10000 --strategy panic|buyhold|momentum|random
```

출력: 엔딩 분포, 최종 자산 중앙값·분포, 파산율, 흔들림 체류 턴 수,
티어 도달 시점 히스토그램. 목표 범위(예: buyhold 파산율 < 5%,
random 파산율 > 30%)를 테스트로 고정한다.

### 8.3 app 테스트

핵심 플로우(턴 진행, 매매, 저장/복원)만. 렌더링 세부는 제외.
